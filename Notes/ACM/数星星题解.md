---

拿到题之后先审题，显然对于100%的数据量是要开long long的。

之后就是算法方面。使用数组储存全部数字，并自前向后遍历每个数，检查其与其余每个数的差是否为num是个容易被想到的思路。但这显然过于繁复，因为每两个数都会被检查2次。

该怎么优化呢？显然对于每个数而言，只需要检查其之后的数而不需要检查它前面的（前面的数已经在它自己的检查过程中检查过了它自己与我们当前的数的差）。

那么按照这种思路，我们写出代码：

```cpp
for(long long i = 0;i < n - 1;i++) { // 最后一项就不用检查了
    for(long long j = i + 1;j < n;j++) {
        if(stars[i] - stars[j] == c || stars[j] - stars[i] == c) cnt++;
    }
}
```

(核心思路，上下略)

超时了。为什么呢？该方法的总执行次数为$(N - 1) + (N - 2) + ...... + 1 = \frac{N(N - 1)}{2}$，时间复杂度为$O(n^{2})$。评测机内1000ms的时间限制通常对应计算机大约能执行 $10^{7} \sim 10^{8}$ 次基本运算,对于$O(n^{2})$的算法只能支持$N$在$5000 \sim 10000$的数据规模。题目给出了$N \le 2 \times 10^{5}$，显然远大于它。

---

进一步怎么优化？这里介绍一种新的数据结构：哈希表（map）

详细介绍可以看[OI WIKI](https://oi-wiki.org/ds/hash/)，这里只看我们需要的用法：

```cpp
map<type1, type2> m;
```

这是什么意思呢？我们首先注意到其类型构造接收两个类型,`type1`和`type2`,他们分别表示“键（key）”和“值（value）”的类型。举个例子：

```cpp
map<string, int> m;
```

表示一个键为字符串，值为32为整型的map。我们可以这样使用它：

```cpp
m["Hello"] = 1; // 赋值。若本来不存在键为“Hello”的项则新建它并赋值为1,若已存在则修改其值为1.
cout << m["Hello"] << endl; // 读取
```

很像数组对吧。可以暂时将他看作一个高级的数组，但其键可以为任意类型。

---

回到本题，我们可以考虑使用哈希表存储全部出现过的数字和他们的出现次数：

```cpp
map<long long, long long> exist;
for(int i = 0; i < n; i++) {
    int x;
    cin >> x;
    if(exist.find(x) != exist.end()) exist[x]++;
}
```

为什么不用普通数组？因为普通数组是连续的，一定是从0开始存到n-1。但其中大多数内存在本题中并不被需要，会被浪费，乃至爆内存（MLE）。使用map即可只存需要的，已经出现了的数字。

接下来是要另开循环处理了吗？并不是，只需要在这个循环内一并加上处理即可：

```cpp
for(int i = 0; i < n; i++) {
    // ...
    if(exist.find(x + c) != exist.end()) cnt += exist[x + c];
    if(exist.find(x - c) != exist.end()) cnt += exist[x - c];
}
```

（`exist.find(x + c) != exist.end()`表示`exist`内不存在`x + c`这个键，即`x + c`未出现过。为什么这么写可以查看[OI WIKI](https://oi-wiki.org/lang/csl/associative-container/#map). `exist.find(x - c) != exist.end()`同理）

想一想，**为什么这可行**？

---

因为题目要求的是：

$A - B = C$

也就是差为 `C` 的一对。对于当前读入的数 `x`：

- 如果之前存在 `x + C`，那么 `(x + C) - x = C`，所以它们可以组成一对；
- 如果之前存在 `x - C`，那么 `x - (x - C) = C`，所以它们也可以组成一对。

由于 `C >= 1`，所以 `x + C` 和 `x - C` 都不等于 `x`，不会把自己算进去。

#### 为什么每对只算一次？

假设有一对 `(A, B)` 满足 `A - B = C`，其中 `A > B`。

- 如果先读入 `A`，后读入 `B`：  
  读入 `B` 时，会检查 `B + C = A`，发现 `A` 已经存在，于是加上 `exist[A]`。

- 如果先读入 `B`，后读入 `A`：  
  读入 `A` 时，会检查 `A - C = B`，发现 `B` 已经存在，于是加上 `exist[B]`。

所以不管顺序如何，这一对都会在**后读入的那个数**处理时被统计一次，不会重复也不会漏掉。

#### 重复元素也没问题

比如：

```text
1 1 2 2
C = 1
```

两个 `1` 和两个 `2` 可以组成 `2 * 2 = 4` 对。  
代码会在读入第一个 `2` 时加上 `exist[1] = 2`，读入第二个 `2` 时又加上 `exist[1] = 2`，总共 `4`，正确。

---

完整代码如下：

```cpp
#include <bits/stdc++.h>
using namespace std;

int main() {
    long long n, c, cnt = 0;
    cin >> n >> c;
    
    map<long long, long long> exist;
    for(int i = 0; i < n; i++) {
        int x;
        cin >> x;
        if(exist.find(x) != exist.end()) exist[x]++;
        else exist[x] = 1;

        if(exist.find(x + c) != exist.end()) cnt += exist[x + c];
        if(exist.find(x - c) != exist.end()) cnt += exist[x - c];
    }

    cout << cnt << endl;

    return 0;
}
```
