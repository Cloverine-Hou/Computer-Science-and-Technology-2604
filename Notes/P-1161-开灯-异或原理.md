# 题目描述

在一条无限长的路上，有一排无限长的路灯，编号为 1, 2, 3, 4, ...

每一盏灯只有两种可能的状态，开或者关。如果按一下某一盏灯的开关，那么这盏灯的状态将发生改变。如果原来是开，将变成关。如果原来是关，将变成开。

在刚开始的时候，所有的灯都是关的。小明每次可以进行如下的操作：

指定两个数，a, t（a 为实数，t 为正整数）。将编号为 floor(a), floor(2 * a), floor(3 * a), ..., floor(t * a) 的灯的开关各按一次。其中 floor(k) 表示实数 k 的整数部分。（注：原题此处用的是向下取整符号 ⌊ ⌋，用 floor 等效说明）

在小明进行了 n 次操作后，小明突然发现，这个时候只有一盏灯是开的，小明很想知道这盏灯的编号，可是这盏灯离小明太远了，小明看不清编号是多少。

幸好，小明还记得之前的 n 次操作。于是小明找到了你，你能帮他计算出这盏开着的灯的编号吗？

## 输入格式

第一行一个正整数 n，表示 n 次操作。

接下来有 n 行，每行两个数，a<sub>i</sub>, t<sub>i</sub>。其中 a<sub>i</sub> 是实数，小数点后一定有 6 位，t<sub>i</sub> 是正整数。

## 输出格式

仅一个正整数，那盏开着的灯的编号。

# 题解原理深度解析

这个题解的核心原理是**利用异或（XOR）运算的特性来判断奇偶性**。我们可以分步骤来理解：

## 1. 物理现象转换为数学问题：奇偶性

* 路灯初始全关。
* 按 **1 次** -> 开
* 按 **2 次** -> 关
* 按 **3 次** -> 开

可以发现：**被按了奇数次的灯是开的，被按了偶数次的灯是关的。**

题目已知最后**只有一盏灯是开的**，这意味着：在所有的操作中，这盏灯的编号出现了**奇数次**，而其他所有被操作过的灯的编号都出现了**偶数次**。

## 2. 为什么使用异或（XOR）？

异或运算（符号 `^`）有两个关键特性：
* `a ^ a = 0` （任何数和自己异或等于 0）
* `a ^ 0 = a` （任何数和 0 异或等于它本身）
* 并且异或满足**交换律和结合律**。

题解的做法是：**把所有操作中出现的灯的编号全部异或起来**。
* 如果某盏灯被操作了**偶数次**（比如2次），它的编号在式子中就会出现两次，根据 `a ^ a = 0`，它就会**抵消**掉。
* 如果某盏灯被操作了**奇数次**（比如1次），它就会留到最后。
* 因为题目保证最后只有**唯一一盏**灯亮着，所以把所有出现过的编号异或在一起，互相抵消后，剩下的那个数字，**必然是那盏唯一亮着的灯的编号**。

## 3. 举个简单的例子

假设一共只有 3 次按灯操作，编号分别是：`2`, `2`, `3`。
* 编号2被按了两次（偶数次，最终是关的）；
* 编号3被按了一次（奇数次，最终是开的）。

按照代码逻辑，`ans` 的计算过程如下：
1. 初始 `ans = 0`
2. 遇到 2：`ans = 0 ^ 2 = 2`
3. 遇到 2：`ans = 2 ^ 2 = 0` （2 被抵消了）
4. 遇到 3：`ans = 0 ^ 3 = 3`

最终输出 `3`，完美找出唯一开着的灯。

# 题解代码

```cpp
#include<bits/stdc++.h>
using namespace std;
int n, t, ans, x;
double a;
int main() {
    cin>>n;
    for(int i=1; i<=n; i++) {
        cin>>a>>t;
        for(int j=1; j<=t; j++) {
            x=(int)floor(a*j); // 对应题目：计算当前按下的灯编号 |j*a|
            ans^=x;            // 把该编号累积进行异或
        }
    }
    cout<<ans;
    return 0;
}
```

## 代码细节对应

* `a * j` 是实数，`floor()` 向下取整，完全对应题目操作要求。
* `ans` 初始为 0（`a ^ 0 = a`，不影响结果），不断把当前操作到的灯编号 `x` 异或进去。

## 算法优势

不需要开一个巨大的数组去记录每一个灯的状态（因为灯的编号可能很大，用数组会爆内存），只需要一次遍历。
* **时间复杂度**：O(总操作次数)，极其高效。
* **空间复杂度**：O(1)，只用了几个变量。
