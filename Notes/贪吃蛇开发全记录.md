## 1. 项目概况

- **学习者**：大一新生，已学顺序/选择/循环结构、函数、数组、指针、单链表，自学了部分 STL。
- **目标**：用 C++ 做一个控制台贪吃蛇小游戏，按 V1–V6 逐步迭代。
- **要求**：先要文字指导（程序功能、整体设计思路、函数划分、数组存放什么、每版需回顾的知识与难点），不直接给代码；拿不准的地方先提问，不臆想。
- **平台**：Windows 控制台（黑框框）。
- **工具链**：VS Code + MinGW（g++ 16.2.0，路径 `D:\Program Files\W64devkit\w64devkit\bin\g++.exe`）。
- **最终成果**：
  - Version 2.0：菜单 + 越吃越快 + 最高分 + 一键重开
  - Version 3.0：难度选择（Easy / Normal / Hard）
  - Version 4.0：双人对战（WASD vs 方向键、双蛇、双食物、限时、胜负判定）

## 2. 迭代计划

这是最初的版本规划（后来用户删掉了 V6，V5 增加了"不闪屏"）：

| 版本 | 加什么 | 预计耗时 | 验收标准 |
|---|---|---|---|
| V1 | 静态场地 + 蛇 + 食物 | 40 分钟 | 屏幕上出现一个框、一条不动的蛇、一个食物 |
| V2 | 食物随机生成 | 30 分钟 | 反复运行，食物位置不同，且不落在蛇身上 |
| V3 | 蛇会动 + 键盘控制 + 撞墙结束 | 2～3 小时 | 能控制蛇走，撞墙后程序结束 |
| V4 | 吃食物变长 + 分数 | 1 小时 | 吃到食物蛇变长、分数增加 |
| V5 | 撞自己结束 + 重开 | 1 小时 | 撞到自己会死，能重新开始 |
| V6 | 不闪烁 + 调速 + 暂停 | 2 小时 | 画面稳定不闪，速度随分数加快 |

实际执行时：V5 改为"撞自己 + 运动时不闪屏"，V6 被取消，功能并入 Version 2.0 / 3.0 / 4.0。

## 3. 环境与选型

### 3.1 已确认的选择

| 项目 | 选择 |
|---|---|
| 运行界面 | Windows 控制台黑框框 |
| 编译器 | VS Code + MinGW（g++） |
| 蛇身存储 | 最初选 STL `deque`，实际实现改成定长数组 `Point snake[MAXLEN]` |
| STL 限制 | 能用就用，不限制 |

### 3.2 最终的项目约定

- 场地：`W = 50`，`H = 25`（含左右墙、上下墙），内部可走区域 `1..W-2` / `1..H-2`。
- 每个逻辑格在屏幕上占 **1 个字符**（V1 曾用 2 字符，V3 因"竖直蛇变粗"改回 1 字符，见 5.3）。
- 字符集：全 ASCII，避免中文乱码。
  - 墙：`|`（左右）、`+ -`（上下）
  - 蛇 1：`@`（头）、`o`（身）
  - 蛇 2：`#`（头）、`x`（身）
  - 食物：`$`
- 蛇身用定长数组：`snake[0]` 是头，`snake[1..snakeLen-1]` 依次往尾巴；`MAXLEN = W*H`。
- 渲染分层：`BuildFrame` 只写字符缓冲 `grid[H][W]`（"这一帧画什么"，不是游戏状态），`DrawFrame` 只负责输出。
- 上下墙不进 `grid`，由 `DrawFrame` 直接拼接（原因见 5.1）。

## 4. 设计指导（最初的核心文档）

这是项目开始时给出的完整设计指导，后续所有版本都遵循它。

### 4.1 程序功能描述

**界面布局（逻辑示意）**

```
 分数: 0    长度: 3    速度: 1    最高: 0
 +----------------------------------+
 |                                  |
 |                                  |
 |            @oo                   |
 |                     $            |
 |                                  |
 |                                  |
 +----------------------------------+
 WASD/方向键移动 · 空格暂停 · R 重开 · Q 退出
```

- 四周是墙，内部是活动区（最初 25 列 × 18 行，实际 50 × 25）。
- `@` 蛇头、`o` 蛇身、`$` 食物、`#`/`+ -`/`|` 墙体。
- 顶部一行 HUD 显示分数、长度、速度档、最高分。
- 底部一行提示操作键。
- **整屏只用 ASCII 字符**（避免 GBK/UTF-8 乱码）。

**操作方式**

| 按键 | 作用 |
|---|---|
| W/A/S/D 或 ↑↓←→ | 转向（不能 180° 反向） |
| 空格 | 暂停 / 继续（V6） |
| R | 死亡后重开（V5） |
| Q 或 Esc | 退出 |

**规则与计分**

- 蛇初始 3 节，位于场地中央，朝右，每 `interval` 毫秒前进一格。
- 吃到食物：长度 +1、分数 +10、立刻生成新食物、速度小幅提升（有下限）。
- 撞墙或撞自己：进入 GAME_OVER，显示本局分数与最高分，按 R 重开、Q 退出。
- 食物永远不会出现在蛇身、墙体上。

**状态机（V5 之后的核心结构）**

```
READY ──按键──> RUNNING ──空格──> PAUSED
                   │  ↑                │
                   │  └────空格────────┘
                   │撞墙/撞自己
                   ↓
               GAME_OVER ──R──> RUNNING
                   │
                   └──Q──> EXIT
```

不要用一堆 `if` 拼状态，用 `enum class GameState` 加 `switch`，后面加功能会轻松很多。

**可选扩展（V6 之后有余力再说）**

最高分存文件、穿墙模式、难度选择、`Beep()` 音效、双人模式。

### 4.2 整体设计思路

**分层结构**

```
main()
 └─ GameLoop()            主循环：固定节拍
     ├─ PollInput()       ← 输入层：只读键，只改"意图"
     ├─ Update()          ← 逻辑层：按累计时间推进一步或多步
     │   └─ Step()        ← 单步：算新头 → 判撞 → 判吃 → 更新容器
     │       └─ SpawnFood()
     └─ Render()          ← 渲染层：状态 → 字符缓冲 → 只输出变化格
         ├─ BuildFrame()
         └─ DrawFrame()
```

**主循环必须遵循一条原则**：输入、逻辑、渲染三者互不越界。

- `PollInput` 不移动蛇，只记录"待处理方向"和"暂停/重开"请求。
- `Step` 不打印任何东西。
- `Render` 不修改游戏状态。

**六条设计原则**

1. **单一数据源**：屏幕上的每个字符都由 `GameState` 推导出来，绝不允许"画的时候顺便改状态"。
2. **输入与逻辑解耦**：按键只写 `pendingDir`，`Step` 执行时才消费它。这样能天然防住"一帧内连按两次导致自杀"。
3. **固定节拍 + 真实时间**：用真实时钟判断"距上次前进是否满 interval"，`Sleep` 只负责让出 CPU。这样 Sleep 的误差不会累积成"越走越快"。
4. **渲染做差量**：维护上一帧字符缓冲，只重画变化的格子。这是 V6 不闪烁的根本手段。
5. **状态与显示分离**：蛇的真实状态是数组和占用表，**不是**二维 char 地图。地图只是"这一帧怎么画"。
6. **坐标统一约定**：逻辑坐标 `(x=列, y=行)`，屏幕坐标 = 逻辑坐标 × 缩放 + 偏移。全项目只用一套约定，否则必出"上下颠倒/左右反了"。

**坐标与显示的两个硬约定**

- **一格画 2 个字符宽**（最初方案）：终端字符高约为宽的 2 倍，一格只画 1 个字符，20×20 的地图会变成竖长条。所以每格输出 `"OO"`、`"@ "`、`"$ "` 这类两字符。（V3 改为 1 字符，见 5.3）
- **用光标定位逐格输出，不要用换行拼整屏**：一旦输出到窗口底部会触发滚屏，整个画面会上移、边框错位。这是控制台游戏最经典的坑。

### 4.3 数据结构（含数组各存什么）

**总表**

| 名字 | 类型 | 存什么 | 谁写 | 谁读 |
|---|---|---|---|---|
| `snake_` | `std::deque<Point>` 或 `Point snake[MAXLEN]` | 所有蛇身格坐标，`front` / `[0]` 是蛇头 | Step | 渲染、判撞、生成食物 |
| `dir` / `pendingDir` | 方向枚举 | 当前实际方向 / 缓冲中待生效方向 | 前者 Step，后者 PollInput | Step |
| `food` | `Point` | 食物坐标 | SpawnFood | 渲染、Step |
| `score` `len` `speed` `highScore` | `int` | 分数、长度、速度档、最高分 | Step | HUD |
| `state` | 枚举 | READY/RUNNING/PAUSED/GAME_OVER/EXIT | PollInput、Step | 全体 |
| `lastStep` | 时钟时间点 | 上次前进的时刻 | Update | Update |

所有状态建议**聚在一个 `struct GameState`** 里，函数统一用 `GameState&` 传，比满地全局变量好调试得多。

**蛇容器的约定（先定死，别中途改）**

- `front` / `[0]` 是蛇头，`back` / `[len-1]` 是蛇尾。
- 走一步：插入新头；**没吃到**食物才删尾。
- 变长：吃到食物时**不删尾**。就这一条差别，V4 的全部复杂度都在这里。
- 为什么用 `deque` 不用 `vector`：`vector` 头部插入是 O(n)，`deque` 两端都是 O(1)。

**数组/连续容器各存什么**

| 名字 | 类型 | 存什么 | 用在哪版 |
|---|---|---|---|
| `frame_` | `vector<char>`，大小 `W*H` | **一帧的字符缓冲**：每个元素是一个格子要显示的字符（空/墙/蛇身/蛇头/食物） | V6 双缓冲 |
| `prevFrame_` | 同上 | **上一帧字符缓冲**，与 `frame_` 逐格比较得出差异 | V6 |
| `occupied_` | `vector<char>` 或 `bool`，大小 `W*H` | **蛇身占用表**：某格是否被蛇占据，用来 O(1) 判"撞自己"和"找空格放食物" | V2 起用，V5 关键 |
| `keyTable_` | 小映射 | 按键字符 → 方向枚举 | V3 |
| `speedTable_` | `int` 数组 | 分数段 → 帧间隔（可选，比一堆 `if` 清爽） | V6 |

要点：**`frame_` 是"显示"，`occupied_` 是"状态"**，两者职责不同，不要混成一个二维地图，否则 V6 做差量渲染时会很痛苦。

### 4.4 函数划分

**调用关系**

```
main → GameLoop
        ├─ PollInput      （输入层）
        ├─ Update         （逻辑层） → Step → SpawnFood
        └─ Render         （渲染层） → BuildFrame → DrawFrame / DrawHUD / DrawGameOver
平台层被以上所有层调用：InitConsole / GotoXY / KeyPressed / ReadKey / SleepMs
```

**平台层（和游戏无关，可单独调试）**

| 函数 | 职责 | 首次出现 |
|---|---|---|
| `InitConsole()` | 隐藏光标、关快速编辑模式、设置窗口大小 | V1 |
| `GotoXY(x,y)` | 把光标移到屏幕某格 | V1 |
| `KeyPressed()` | 非阻塞判断有没有按键（`_kbhit`） | V3 |
| `ReadKey()` | 读一个键，处理方向键的两字节前缀 | V3 |
| `SleepMs(ms)` | 包装 `Sleep` | V3 |
| `ClearScreen()` | 清屏（V6 后基本不用） | V1 |

**输入层**

| 函数 | 职责 | 版本 |
|---|---|---|
| `PollInput(g)` | 每帧调用一次；把按键翻译成 pendingDir / 暂停 / 重开 / 退出 | V3（V5/V6 扩充） |

**逻辑层**

| 函数 | 职责 | 版本 |
|---|---|---|
| `InitGame(g)` / `ResetGame(g)` | 完整初始化（重开也调用它，所以必须可重复调用） | V1 |
| `SpawnFood(g)` | 在空格中随机放食物 | V2 |
| `IsOpposite(a,b)` | 两个方向是否相反 | V3 |
| `WillHitWall(g,p)` | 坐标越界判定 | V3 |
| `WillHitSelf(g,p)` | 新头是否撞身体（注意尾巴特例） | V5 |
| `Step(g)` | 推进一步：算新头 → 判撞 → 判吃 → 更新容器/分数/速度 | V3（V4/V5 扩充） |
| `Update(g, now)` | 按真实时间决定走 0/1/多步；处理暂停与结束态 | V3（V6 改造） |

**渲染层**

| 函数 | 职责 | 版本 |
|---|---|---|
| `BuildFrame(g)` | 把状态写进 `frame_` 数组 | V1（V6 改写） |
| `DrawFrame(g)` | 输出 `frame_`；V6 起只输出与 `prevFrame_` 不同的格 | V1（V6 改写） |
| `DrawHUD(g)` | 画分数/长度/速度/最高分 | V4 |
| `DrawGameOver(g)` / `DrawPaused()` | 覆盖层文字 | V5 / V6 |

**主控**

| 函数 | 职责 |
|---|---|
| `GameLoop(g)` | 读输入 → 逻辑 → 渲染 → 睡到下一拍，循环直到 EXIT |
| `main()` | 初始化控制台、初始化游戏、进循环、收尾 |

**传参约定（很重要）**

- 改状态的：`GameState& g`
- 只读的：`const GameState& g`
- 不传全局变量，`g` 一路传下去。大一阶段养成这个习惯，后面写大作业会轻松很多。

### 4.5 每版需回顾的知识与难点

#### V1（40 分钟）静态场地 + 蛇 + 食物

**需回顾的知识**
- 常量与宏：`W`、`H`、偏移量全部定义成常量，不许写魔数。
- 二维数组的下标与遍历、嵌套循环。
- 函数定义、声明、调用；`void` 函数与返回值函数。
- 字符输出、定位输出。
- 逻辑坐标 `(x,y)` 与屏幕行列 `(row,col)` 的换算。

**难点 / 易错点**
- 一格画 2 字符：不处理的话方框会变竖长条。
- 边界与内部混淆：`x==0 || x==W-1 || y==0 || y==H-1` 是墙，内部才是活动区。
- 用换行拼整屏 → 滚屏 → 边框错位。必须逐格定位输出。
- 蛇的数据结构现在就要定死（front 是头、初始 3 节朝右），别等 V3 再改。
- 别在 `main` 里堆输出，`BuildFrame`/`DrawFrame` 从第一版就分出来。

**引导要点**
先把"画边框"跑通，再加"画固定蛇"，再加"食物"，三步各自能跑再合并。做完这版就有了**渲染层的骨架**。

#### V2（30 分钟）食物随机生成

**需回顾的知识**
- `rand()` + `srand(time(nullptr))`，或 `<random>` 的 `mt19937` + `uniform_int_distribution`。
- 取模映射到区间 `[1, W-2]`、`[1, H-2]`；`rand()%n` 的轻微偏差。
- 循环 + 条件 + 提前 `break`。
- 数组遍历。

**难点 / 易错点**
- 排除蛇身：拒绝采样（"随机到蛇身就重抽"）在蛇很长时可能抽很多次甚至死循环，**必须有尝试次数上限**，或先收集所有空格再随机取一个。
- 食物范围不能贴墙外，`x` 必须在 `1..W-2`。
- 可复现性：调试时用**固定种子**，否则 bug 重现不了。
- `srand` 只在 `main` 里调一次，别在循环里调，否则每次同一序列。
- 食物可能刚好落在蛇头正前方，这是正常现象，不用特判。

**引导要点**
这版就把占用表建起来：初始化和每次移动时同步维护。它现在只是"查重更方便"，到 V5 判撞自己时价值才真正体现。

#### V3（2–3 小时）蛇会动 + 键盘 + 撞墙

**需回顾的知识**
- 循环、`switch`、`enum class`。
- 引用传参、`const` 引用。
- `<conio.h>` 的 `_kbhit()` / `_getch()`；理解"非阻塞"和"阻塞"的区别。
- `Sleep()`（`<windows.h>`）；帧间隔概念。
- 数组的移位（头进尾出）。

**难点 / 易错点**
1. **不能用 `cin >>`**：它会卡住等回车。必须 `_kbhit` 探测 + `_getch` 读取。
2. **方向键是两个字节**：`_getch()` 先返回 `0` 或 `224`，要再读一次才是 `72/80/75/77`。所以这版建议先用 WASD，方向键作为加分项。
3. **反向自杀**：向右走时快速按"上"再按"左"，如果直接改方向，第二次判断时"左"并不与"上"相反，但实际会撞自己。解法就是 `pendingDir` 单槽缓冲：一帧只接受一次有效转向，且必须先与**当前方向**比较是否相反。
4. **头进尾出**：插入新头之后要删尾，顺序反了会多一格。
5. **撞墙要"预测"**：先算新头坐标再判越界，别等画出来才发现。
6. **这一版允许闪**：`system("cls")` 全屏重画先跑通，V6 再治。别在 V3 提前优化。
7. VS Code + MinGW 特有：在集成终端里 `_kbhit` 一般能用；**如果调试时按键没反应**，把 `launch.json` 的 `externalConsole` 设成 `true`，或直接在外部终端跑 exe。这是环境坑，不是代码错。

**引导要点**
分三小步：① 不读键，让蛇自己走（验证移动逻辑）；② 加读键（验证转向）；③ 加撞墙（验证判定）。每步都能单独跑，出问题好定位。

#### V4（1 小时）吃食物变长 + 分数

**需回顾的知识**
- 长度变量的维护、条件分支与状态更新顺序。
- HUD 的定位输出（避开场地，别覆盖格子）。

**难点 / 易错点**
- **吃与不吃只差"这帧删不删尾"**。判定顺序必须固定：算新头 → 判撞墙 → 判是否吃到 → 吃到则长度 +1 且不删尾、加分、生成新食物；没吃到则移位并删尾。
- 顺序错了会出现"吃到但没变长"或"没吃到却变长"这种诡异 bug。
- 生成新食物必须在蛇更新**之后**，否则占用表还是旧的，食物可能生成在新蛇身上。
- 分数显示位置：放框上方一行，别占场地格子。
- 速度变化建议留到 V6 做，这版先固定间隔。

#### V5（1 小时）撞自己 + 重开

**需回顾的知识**
- 数组遍历 / 占用表查表。
- 枚举状态机 + `switch`。
- 函数复用：`InitGame` 与 `ResetGame` 合成一个可重复调用的函数。
- 生命周期的概念：死亡不是"退出程序"，是"切状态"。

**难点 / 易错点**
1. **尾巴特例**：新头坐标等于**当前尾巴**时，如果本帧不吃食物，尾巴会先离开，严格说**不算撞**。很多教程直接判撞，至少要了解这个边界。
2. **判撞时机**：必须在"尾巴离开之前"判断，否则会把"擦着尾巴走"误判成撞。
3. **重开要彻底**：蛇、占用表、帧缓冲、分数、方向、pendingDir、状态、计时器全部重置。只清屏不重置数据，会出现"重开后蛇是上局长度"。
4. **死亡后不能 `exit(0)`**：进 GAME_OVER 状态，等玩家按键。这样最高分、重开才能做。
5. 占用表的维护点：移动时"先加新头、再删旧尾"，删尾要在判定之后。

**引导要点**
把占用表当成"蛇身快照"来用：移动前查新头位置是否被占，注意把"即将离开的尾巴"特判掉。重开就是 `ResetGame` 再回 RUNNING。

#### V6（2 小时）不闪烁 + 调速 + 暂停（实际被替换）

**需回顾的知识**
- 光标定位 API：`SetConsoleCursorPosition`（Windows API）——不推荐赌 ANSI `\033[H`，需要先开 VT 模式，容易白忙。
- 双缓冲 / 差量渲染思想。
- `std::chrono::steady_clock` 测时间；`Sleep` 的精度约 15.6 ms。
- 状态机扩展（PAUSED）。

**难点 / 易错点**
1. **闪烁的根源是"清屏 + 全量重画"**。解决分三级：
   - L1：不 `cls`，光标回 `(0,0)` 覆盖写 → 基本不闪；
   - L2：只重画与上一帧不同的格子 → 最稳，推荐最终方案；
   - L3：整帧拼成一个字符串一次输出 → 也稳，但写入量大时反而慢。
   建议先 L1 跑通，再升 L2。
2. **调速**：分数 → 间隔的映射，线性递减 + 下限，别让速度失控。`Sleep(5)` 实际可能睡 15 ms，别指望毫秒级精确。
3. **暂停必须即时响应**：不能 `Sleep(180)` 一觉睡到底，否则按空格要等最多 180 ms 才生效。做法是把等待**切片**：每 5–10 ms 读一次键，累计够 interval 才走一步。
4. **时间累积**：用 `now - lastStep >= interval` 判定，而不是"睡满 interval 就走一步"，否则 Sleep 误差会累积。
5. **暂停恢复的瞬间**：恢复时把计时基准重置为当前时间，否则会连着走好几步。
6. **HUD 和覆盖层**：PAUSED / GAME OVER 文字要定位输出，恢复时要能擦掉（用空格覆盖），别留下残影。

## 5. 开发实录

### 5.1 V1：静态场地 + 蛇 + 食物

**核心设计约定**

- 逻辑坐标 `(x = 列, y = 行)`，`(0,0)` 在左上角。
- 蛇：`Point snake[MAXLEN]`，`snake[0]` 是蛇头，`snake[1..len-1]` 往尾巴，`MAXLEN = W*H`。
- 渲染分层：`BuildFrame` 只写 `grid[H][W]`（这一帧画什么，不是游戏状态），`DrawFrame` 只输出。
- **上下墙不进 `grid`**，由 `DrawBorder` 直接拼字符串；`grid` 只存内部 + 左右墙。

  原因：2 字符格下角无法对齐——右角 `+` 输出 `"+-"` 会伸出右墙一列；输出 `"+ "` 则左角与横线之间出现空隙。要在 `BuildFrame` 里画上下墙且对齐，得把 `grid` 升级成"屏幕字符缓冲"（宽 2W+1）。当前方案还有个隐性好处：上下墙不变，V6 差量渲染不必重画。

- 函数划分：`InitGame`、`BuildFrame`、`PutCell`、`DrawBorder`、`DrawFrame`、`main`。状态全在 `struct Game`，通过指针/引用传参，不用全局变量。

**V1 完整代码（纯 C 风格，仅 `<stdio.h>`）**

```cpp
/*
 * snake_v1.cpp -- 贪吃蛇 V1：静态场地 + 不动的蛇 + 食物
 * 纯 C 风格：只用 <stdio.h>，不用任何 STL / class / 动态内存 / 平台 API。
 *
 * 编译：
 *   g++ -std=c++17 -Wall -Wextra snake_v1.cpp -o snake_v1.exe
 *   （把文件改名成 .c 用 gcc 编译也可以）
 *
 * 全项目约定（后续版本沿用）：
 *   - 逻辑坐标 (x = 列, y = 行)，(0,0) 在左上角
 *   - snake[0] 是蛇头，snake[1..snakeLen-1] 依次往尾巴走
 *   - grid 只是"这一帧要画什么"的字符缓冲，不是游戏状态本身
 *   - 场地四边是墙：第 0 行 / 第 H-1 行 / 第 0 列 / 第 W-1 列
 */

#include <stdio.h>

#define W 25           /* 场地宽（含左右墙），单位：格 */
#define H 16           /* 场地高（含上下墙），单位：格 */
#define MAXLEN (W * H) /* 蛇的最大长度 */

typedef struct {
    int x, y;
} Point;

typedef struct {
    Point snake[MAXLEN]; /* 蛇身坐标，[0] 是头 */
    int   snakeLen;
    Point food;
    int   score;
    char  grid[H][W];    /* 一帧的字符缓冲：每个元素是一个格子要显示的字符 */
} Game;

/* ---------------------------------------------------------------- */
/* 初始化：蛇（3 节、朝右）、食物、分数                              */
/* ---------------------------------------------------------------- */
static void InitGame(Game *g)
{
    int cx = W / 2;   /* 场地中心列 */
    int cy = H / 2;   /* 场地中心行 */

    g->snakeLen = 3;

    g->snake[0].x = cx;     g->snake[0].y = cy;     /* 头（最右） */
    g->snake[1].x = cx - 1; g->snake[1].y = cy;
    g->snake[2].x = cx - 2; g->snake[2].y = cy;     /* 尾（最左） */

    g->food.x = cx + 6;     /* V2 会换成随机生成 */
    g->food.y = cy - 2;

    g->score = 0;
}

/* ---------------------------------------------------------------- */
/* 把游戏状态写进字符缓冲 grid                                       */
/* 上下两条横墙不写进 grid，由 DrawFrame 直接输出固定字符串          */
/* ---------------------------------------------------------------- */
static void BuildFrame(Game *g)
{
    int x, y, i;

    /* 1. 全部清空 */
    for (y = 0; y < H; y++)
        for (x = 0; x < W; x++)
            g->grid[y][x] = ' ';

    /* 2. 左右墙 */
    for (y = 1; y < H - 1; y++) {
        g->grid[y][0]     = '|';
        g->grid[y][W - 1] = '|';
    }

    /* 3. 先画蛇身，最后画头，保证头一定覆盖身体 */
    for (i = g->snakeLen - 1; i >= 1; i--)
        g->grid[g->snake[i].y][g->snake[i].x] = 'o';
    g->grid[g->snake[0].y][g->snake[0].x] = '@';

    /* 4. 画食物 */
    g->grid[g->food.y][g->food.x] = '*';
}

/* ---------------------------------------------------------------- */
/* 一个格子在屏幕上占 2 个字符宽，否则方框会被拉成竖长条           */
/* ---------------------------------------------------------------- */
static void PutCell(char c)
{
    switch (c) {
    case '|': fputs("| ", stdout); break;
    case 'o': fputs("o ", stdout); break;
    case '@': fputs("@ ", stdout); break;
    case '*': fputs("* ", stdout); break;
    default:  fputs("  ", stdout); break;
    }
}

/* ---------------------------------------------------------------- */
/* 画一条上下边框。宽度与内部行完全一致：2*W+1 个字符              */
/* 列 1 的 '+' 和列 2W-1 的 '+' 分别落在左右墙 '|' 的正上方         */
/* ---------------------------------------------------------------- */
static void DrawBorder(void)
{
    int x;

    putchar(' ');
    putchar('+');
    for (x = 0; x < 2 * (W - 1) - 1; x++)
        putchar('-');
    putchar('+');
    putchar(' ');
    putchar('\n');
}

/* ---------------------------------------------------------------- */
/* 输出整帧（V1 一次性打印；V3 会改成光标定位逐格覆盖）             */
/* ---------------------------------------------------------------- */
static void DrawFrame(const Game *g)
{
    int x, y;

    printf("  Score: %d    Length: %d\n", g->score, g->snakeLen);

    DrawBorder();

    for (y = 1; y < H - 1; y++) {
        putchar(' ');
        for (x = 0; x < W; x++)
            PutCell(g->grid[y][x]);
        putchar('\n');
    }

    DrawBorder();

    printf("  V1 static demo.  WASD control arrives in V3.\n");
}

int main(void)
{
    Game game;

    InitGame(&game);
    BuildFrame(&game);
    DrawFrame(&game);

    printf("\nPress Enter to exit...\n");
    getchar();

    return 0;
}
```

**运行命令**

```powershell

.\snake_v1.exe
```

**V1 遇到的问题**

1. **蛇身显示成 `o o @`（中间有空格）**
   原因：2 字符格 + `PutCell` 只画 1 个字符。
   解决（方案 A）：
   ```cpp
   case '|': cout << "| "; break;
   case 'o': cout << "oo"; break;
   case '@': cout << "@@"; break;
   case '*': cout << "**"; break;
   default:  cout << "  "; break;
   ```
   代价：蛇每节变成 2×1 粗块、与墙同宽；优点：连续，V3 移动观感好。

2. **食物完全不可见**
   原因：`BuildFrame` 存 `'*'`，但 `PutCell` 只写了 `case '$'`，落到 `default` 输出两个空格。这是真 bug。
   修复：`PutCell` 的 `case` 与 `BuildFrame` 里用的字符必须一致。

3. **`getchar()` 的意图**
   暂停等回车再退出，防止双击 exe / IDE 运行时窗口一闪而过。控制台行缓冲要按回车才返回。从 cmd 手动启动时多余；V3 用 `_getch` 后必须删（启动会卡住，且与 `_getch` 底层缓冲混用）。替代品 `_getch()`（任意键）优于 `system("pause")`（依赖 cmd、慢）。

### 5.2 V2：食物随机生成

**要点**

- `main` 开头 `srand((unsigned)time(NULL));` 只调用一次；不能放进 `SpawnFood`（同一秒内序列相同）。
- `OnSnake` 遍历全部 `snakeLen` 节。
- `SpawnFood` 用拒绝采样，范围 `1..W-2`：
  ```cpp
  do {
      x = rand() % (W - 2) + 1;
      y = rand() % (H - 2) + 1;
  } while (OnSnake(*g, x, y));
  ```
- `SpawnFood` 不能写进 `BuildFrame`（每帧调用会乱跳）。
- `InitGame` 里在蛇初始化之后调用；为 V4 复用。
- 蛇很长时拒绝采样可能抽很多次，工程上应加尝试上限或先收集空格。

**验收**：反复运行，食物位置不同，且不落在蛇身上。

### 5.3 V3：蛇会动 + 键盘控制 + 撞墙结束

**知识点**

- `<conio.h>`：`_kbhit()` 不消耗按键；`_getch()` 不回显、不等回车。
- 方向键两字节：前缀 `0` 或 `224`，第二次 `_getch()` 才是扫描码（上 72、下 80、左 75、右 77）。
- 每帧 `while (_kbhit())` 读空缓冲，不要用 `if`。
- 防反向：按键只写 `pendingDir`（过滤当前 `dir` 的反向），每帧 `dir = pendingDir`；`Opposite(Dir)` 小函数。
- 主循环：读键 → 采纳方向 → 算新头 → 判撞墙 → 移位 → `BuildFrame` → `system("cls")` → `DrawFrame` → `Sleep`。
- `Sleep` 在 `<windows.h>`，精度约 15.6 ms；V3 固定 150～250 ms。
- 撞墙：`nextX<=0 || nextX>=W-1 || nextY<=0 || nextY>=H-1`（可走 1..W-2）。
- 用 `over` 标志结束，不要 `exit(0)`（给 V5 重开留结构）。
- `system("cls")` 会闪，V3 正常，V6 再治。
- 分步实现：① 自动向右走 + 撞墙结束（不接键盘）② 读键打印键值 ③ 接 `pendingDir` ④ 防反向过滤。

**用户 V3 首版的两个 bug**

1. **`Step` 只算新头 + 判撞墙，忘了移位与更新 `snake[0]`** → 蛇头坐标永远不变 → 撞墙条件永不成立 → `over` 永假 → `while` 死循环。
   修复：
   ```cpp
   // 撞墙 return 之后补：
   for (int i = len - 1; i > 0; i--)
       snake[i] = snake[i - 1];
   snake[0].x = nextX;
   snake[0].y = nextY;
   ```

2. **`main` 里没有 `system("cls")`** → 每 500 ms 追加整屏 → 滚屏。
   修复：每帧 `BuildFrame` 后 `system("cls")` 再 `DrawFrame`。

**竖直蛇变粗 → 改 1 字符/格**

原因：每格 2 字符导致竖直时每行 `"oo"` 2 字符宽；在 2 字符/格的前提下，"水平连续"与"竖直细线"不可兼得。

采纳 1 字符/格方案：

- `W = 50`，`H = 25`（`W ≈ 2H` 保持视觉方形）；
- `PutCell` 直接输出单字符；
- `DrawFrame` 顶/底边 `" +" + (W-2) 个 '-' + '+'`（总宽 `W+1` = 内部行 `1+W`，`+` 与左右墙对齐）；
- 速度改 200–250 ms。

**用户 V3 完整代码**

```cpp
//目标：蛇会动了 能控制蛇转向 撞到墙就游戏结束
#include <bits/stdc++.h>
#include <conio.h>
#include <windows.h>
using namespace std;
#define endl '\n'
#define W 50           //场地宽（含左右墙）
#define H 25           //场地高（含上下墙）
#define MAXLEN (W * H) //蛇最大长度
typedef struct {
    int x, y;
} Point;
typedef struct {
    Point snake[MAXLEN]; //蛇身坐标 [0]是头
    int   snakeLen;
    Point food;
    int   score;
    char  grid[H][W];    //每个元素是一个格子要显示的字符
    bool  over;
} Game;
//判定所输入的坐标（比如食物坐标）是否在蛇身上
bool OnSnake(const Game &g,int x,int y){
    for(int i=0;i<g.snakeLen;i++){
        if(g.snake[i].x==x && g.snake[i].y==y){
            return true;
        }
    }
    return false;
}
//随机生成食物坐标（还没绘制出来） 如果被蛇占用了就继续跑循环 直到发现未被蛇占据的为止
void SpawnFood(Game *g){
   do{
    g->food.x=rand()%(W-2)+1; //墙的列标是0和W-1 要产生1~W-1的随机数作为食物的列标
    g->food.y=rand()%(H-2)+1; //墙的行标是0和H-1 要产生1~H-1的随机数作为食物的列标
   }while(OnSnake(*g,g->food.x,g->food.y));
}
static void InitGame(Game *g)
{
    g->over=false;
    int cx = W / 2;   //场地中心列
    int cy = H / 2;   //场地中心行
    g->snakeLen = 3;
    g->snake[0].x = cx;     g->snake[0].y = cy;     //头
    g->snake[1].x = cx - 1; g->snake[1].y = cy;
    g->snake[2].x = cx - 2; g->snake[2].y = cy;     //尾
    //V2此处改成随机生成食物
    SpawnFood(g);
    g->score = 0;
}
void Step(Game &g, int dirX, int dirY){
    //计算新蛇头坐标
    int nextX=g.snake[0].x+dirX;
    int nextY=g.snake[0].y+dirY;
    //撞墙检测
    if (nextX<=0||nextX>=W-1||nextY<=0||nextY>=H-1){
        g.over=true;
        return;
    }
    for (int i=g.snakeLen-1;i>0;i--)
        g.snake[i]=g.snake[i-1];
    //新头
    g.snake[0].x=nextX;
    g.snake[0].y=nextY;
}
static void BuildFrame(Game *g)
{
    int x, y, i;
    //全部清空
    for (y = 0; y < H; y++)
        for (x = 0; x < W; x++)
            g->grid[y][x] = ' ';
    //左右墙
    for (y = 1; y < H - 1; y++) {
        g->grid[y][0]     = '|';
        g->grid[y][W - 1] = '|';
    }
    //蛇身
    for (i=g->snakeLen-1;i>=1;i--){
        g->grid[g->snake[i].y][g->snake[i].x] = 'o';
    }
    //蛇头
    g->grid[g->snake[0].y][g->snake[0].x] = '@';
    //食物
    g->grid[g->food.y][g->food.x] = '$';
}
static void PutCell(char c)
{
    switch (c) {
    case '|': cout<<"|"; break;
    case 'o': cout<<"o"; break;
    case '@': cout<<"@"; break;
    case '$': cout<<"$"; break;
    default:  cout<<" "; break;
    }
}
static void DrawFrame(const Game *g)
{
    int x, y;
    cout<<"Score:"<<g->score<<" "<<"Length:"<<g->snakeLen<<endl;
    //顶边 +------+ 样式
    cout<<" ";
    cout<<"+";
    for(x=0;x<W-2;x++){
        cout<<"-";
    }
    cout<<"+"<<endl;
    //中间
    //先给场地里面全打空格
    for(y=1;y<H-1;y++){
        cout<<" ";
        //再填充内部内容（蛇身 蛇头 食物）
        for(x=0;x<W;x++){
            PutCell(g->grid[y][x]);
        }
        cout<<endl;
    }
    //底边 和顶边一样 +------+ 样式
    cout<<" ";
    cout<<"+";
    for(x=0;x<W-2;x++){
        cout<<"-";
    }
    cout<<"+"<<endl;
    cout<<"V3 static demo allows WASD control."<<endl;
}
int main()
{
    //初始让蛇向右运动
    int dirX=1,dirY=0;
    srand((unsigned)time(NULL));
    Game game;
    InitGame(&game);
    while (game.over==false){
        //绘制初始框架
        BuildFrame(&game);
        system("cls");
        DrawFrame(&game);
        //移动一步
        if(_kbhit()){
            char key=_getch();
            //根据输入WASD来控制后续移动的方向 同时为了防止自己反转撞自己 只有非反转的输入才生效
            if((key=='w'||key=='W') && dirY!=1){
                dirX=0;
                dirY=-1;
            }else if((key=='a'||key=='A') && dirX!=1){
                dirX=-1;
                dirY=0;
            }else if((key=='s'||key=='S') && dirY!=-1){
                dirX=0;
                dirY=1;
            }else if((key=='d'||key=='D') && dirX!=-1){
                dirX=1;
                dirY=0;
            }
        }
        Step(game,dirX,dirY);
        //延时控制速度
        Sleep(250);
    }
    cout<<"Game over:hit the wall."<<endl;
    getchar();
    return 0;
}
```

**V3 验收结论**：达标（能控制蛇走、撞墙结束）。遗留：`food` 先画还是后画（食物被蛇盖住）、`_getch` 返回值用 `int`、`if(_kbhit())` 改 `while` 读空、参数风格统一。

### 5.4 V4：吃食物变长 + 分数

**判定顺序（必须固定）**

算新头 → 撞墙 → `bool ate = (nextX==food.x && nextY==food.y)` → 若 `ate` 且 `snakeLen < MAXLEN` 则 `snakeLen++`（先加长度，尾巴保留）→ 移位（循环起点用新 `snakeLen-1`）→ `snake[0]=next` → 若 `ate` { `score++`; `SpawnFood(&g)`; }。

**SpawnFood 必须在蛇头更新之后调用**。

用户 V4 代码里的 bug：把 `SpawnFood` 写进了 `ate` 分支开头（蛇头更新之前）：

```cpp
if(ate==true){
    g.snakeLen++;
    g.score++;
    SpawnFood(&g);   // ← 太早
}
for (...) 移位;
g.snake[0] = next;
```

后果：

1. 此时 `snake[0]` 还是旧头，`OnSnake` 看不到新头 → 新食物可能正好生成在 `(nextX, nextY)`，即蛇头马上要占的格子 → 食物与蛇头重叠（下一帧被盖住，看起来"食物消失"）。
2. `snakeLen` 已 +1，但 `snake[snakeLen-1]` 还没初始化（移位还没做）→ `OnSnake` 读到垃圾坐标（未定义行为）。

修复：

```cpp
if (ate && g.snakeLen < MAXLEN) {
    g.snakeLen++;
}
for (int i = g.snakeLen - 1; i > 0; i--)
    g.snake[i] = g.snake[i - 1];
g.snake[0].x = nextX;
g.snake[0].y = nextY;
if (ate) {
    g.score++;
    SpawnFood(&g);
}
```

**其他小问题**

- `if(ate==true)` 可简化为 `if(ate)`。
- `MAXLEN` 保护缺失（长到极限会越界；50×25 场地几乎不会满，但加上更稳）。
- `Sleep(100)` 偏快。
- `lenth` 拼写错误。

**验收**：吃一次长度 3→4、分数 +1、食物随机重生、撞墙仍结束。

### 5.5 V5：撞自己结束 + 不闪烁

**撞自己判定**

- 用 `snake` 数组判定，不用 `grid`（`grid` 是上一帧字符快照、含墙和食物）。
- **尾巴特例**：不吃时尾巴同帧移走，新头进旧尾格合法；吃到时尾巴不动，压上去算撞。
- **推荐：先移后判**——移位 + 写新头完成后，遍历 `snake[1..snakeLen-1]`，尾巴特例自动正确。
- 判定顺序：算新头 → 撞墙 `return` → 判吃 → 调长度 → 移位 + 写头 → **撞自己判定**（撞了记死因 `return`，不再加分/重生食物）→ 若吃加分 + `SpawnFood`。
- 死因区分：`deathreason`（1 撞墙 / 2 撞自己），循环外按死因打印。
- 测撞自己：先吃到 5～6 节再绕 2×2 / 3×3 小圈；贴尾巴转弯验证特例。

**不闪屏方案**

闪烁的本质：`system("cls")` 清屏→重画的空白阶段被看到。

方案 A（实际采用）：不再清屏，每帧把光标移回 `(0,0)` 整帧覆盖；隐藏光标；HUD 行尾补空格防数字位数残留。

```cpp
// 取一次控制台输出句柄，定位光标、隐藏光标都要用它
static HANDLE ConsoleOut()
{
    return GetStdHandle(STD_OUTPUT_HANDLE);
}

// 隐藏光标

{
    CONSOLE_CURSOR_INFO info;
    info.dwSize = 100;
    info.bVisible = FALSE;
    SetConsoleCursorInfo(ConsoleOut(), &info);
}

// DrawFrame 开头：
COORD origin = {0, 0};

```

main 里删掉循环里的 `system("cls")`，循环前调用 `HideCursor()`。原理：cls 清屏→重画的空白阶段就是闪；覆盖没有空白帧。

方案 B（差量渲染，留作进阶）：维护上一帧 `grid`，只重画变化的格子。

**黑屏事故**：编译通过但终端什么都不显示

1. 该调用让 `cout` 与 `stdout` 解绑，变成全缓冲；

4. 与 `SetConsoleCursorPosition` 的定位错位 → 画面滚出可视区，看起来空白。

修复：删掉 `ios::sync_with_stdio(false)`，或在 `DrawFrame` 末尾显式 `cout.flush();`。

同时修复：

- 最高分比较写在 `if(ate)` 开头（`score++` 之前）→ 永远少 1 → 移到 `score++` 之后。

### 5.8 Version 4.0：双人对战

**需求**

- 双人模式：WASD 控制玩家 1，方向键控制玩家 2；双蛇初始长度 3、默认向右、分居中央上下两侧；各自独立状态（长度、方向、得分）。
- 两级菜单：先难度，再模式（S 单人 / D 双人）。
- 双倍食物：场上常驻 2 个食物，适配双蛇觅食。
- 限时对战：倒计时结束后按得分判定胜负。
- 不大幅改动原代码、不删原注释、所有改动用 `Version4.0新增` / `Version4.0修改` 注释标出。

**胜负规则**

- 一方死亡、另一方存活 → 存活者立即获胜；
- 同帧双亡 → 比分，分数相同平局；
- 时间到 → 比分，相同平局。

**规则实现细节**

- 双蛇互撞：头碰到对方任意一节（包括对方头）就死；对头相撞算双方都死（比得分）。
- 双人模式"对手尾巴也不能踩"（判定在移动后统一做，规则简单、可解释）。
- 双人模式两人共用同一个 `speed`，任一人吃到食物全场加速（公平）。
- `highestscore` 保持单人专属，双人模式不更新。

**完整代码**

#include <conio.h>
#include <windows.h>
using namespace std;
#define endl '\n'
#define W 50           //场地宽（含左右墙）
#define H 25           //场地高（含上下墙）
#define MAXLEN (W * H) //蛇最大长度
//Version4.0新增 双人对战模式的限时（秒），要改时长只改这一处
#define MATCH_TIME 90
typedef struct {
    int x, y;
} Point;
typedef struct {
    Point snake[MAXLEN]; //蛇身坐标 [0]是头
    int   snakeLen;
    Point food;
    int   score;

    bool  over;
    int   deathreason;   //V5新增 说明游戏结束的原因：撞墙 还是 撞到自己
    int   speed;         //Version2.0新增 用于修改Sleep();
    int   highestscore;  //Version2.0新增 最高记录统计
    int   difficulty;    //★V3.0新增 所选难度：0=Easy 1=Normal 2=Hard
    int   speedMin;      //★V3.0新增 当前难度允许的最快速度（speed 的下限）
    //====下面是Version4.0新增的字段====
    int   mode;          //Version4.0新增 游戏模式：0=单人 1=双人
    Point snake2[MAXLEN];//Version4.0新增 玩家2的蛇身坐标 [0]是头
    int   snakeLen2;     //Version4.0新增 玩家2的蛇长

    int   timeLeft;      //Version4.0新增 双人模式剩余秒数
    int   timeAcc;       //Version4.0新增 毫秒累加器（把每帧Sleep累加成秒）

} Game;
//判定所输入的坐标（比如食物坐标）是否在蛇身上
bool OnSnake(const Game &g,int x,int y){
    for(int i=0;i<g.snakeLen;i++){
        if(g.snake[i].x==x && g.snake[i].y==y){
            return true;
        }
    }
    return false;
}
//随机生成食物坐标（还没绘制出来） 如果被蛇占用了就继续跑循环 直到发现未被蛇占据的为止
void SpawnFood(Game *g){
   do{
    g->food.x=rand()%(W-2)+1; //墙的列标是0和W-1 要产生1~W-2的随机数作为食物的列标 *V3已修复注释错误 应该是W-2
    g->food.y=rand()%(H-2)+1; //墙的行标是0和H-1 要产生1~H-2的随机数作为食物的列标 *V3已修复注释错误 应该是H-2
   }while(OnSnake(*g,g->food.x,g->food.y));
}
//Version4.0新增 判定坐标是否在玩家2的蛇身上
static bool OnSnake2(const Game &g,int x,int y){
    for(int i=0;i<g.snakeLen2;i++){
        if(g.snake2[i].x==x && g.snake2[i].y==y){
            return true;
        }
    }
    return false;
}
//Version4.0新增 判定坐标是否落在任意一条蛇身上（双人模式生成食物用）
static bool OnAnySnake(const Game &g,int x,int y){
    if(OnSnake(g,x,y)) return true;
    if(g.mode==1 && OnSnake2(g,x,y)) return true;
    return false;
}
//Version4.0新增 双人模式生成食物：避开两条蛇，同时避开另一个食物
static void SpawnFoodDuel(Game *g,bool forPlayer2){
    int x,y;
    do{
        x=rand()%(W-2)+1;
        y=rand()%(H-2)+1;
    }while(OnAnySnake(*g,x,y)
          || (forPlayer2 ? (x==g->food.x  && y==g->food.y)
                         : (x==g->food2.x && y==g->food2.y)));
    if(forPlayer2){ g->food2.x=x; g->food2.y=y; }
    else          { g->food.x =x; g->food.y =y; }
}
static void InitGame(Game *g)
{
    g->over=false;
    g->deathreason=0;   //V5新增 初始化deathreason为0
    int cx = W / 2;     //场地中心列
    int cy = H / 2;     //场地中心行

    if (g->mode == 1) {
        cy = H / 3;
    }
    g->snakeLen = 3;
    g->snake[0].x = cx;     g->snake[0].y = cy;     //头
    g->snake[1].x = cx - 1; g->snake[1].y = cy;
    g->snake[2].x = cx - 2; g->snake[2].y = cy;     //尾
    //V2此处改成随机生成食物
    SpawnFood(g);
    g->score = 0;
    // ★V3.0修改：原来的 g->speed = 200; 改为按难度初始化速度与下限
    //Version2.0新增 初始化speed=200
    if (g->difficulty == 0) {          // Easy
        g->speed = 300;
        g->speedMin = 100;
    } else if (g->difficulty == 1) {   // Normal
        g->speed = 200;
        g->speedMin = 50;
    } else {                           // Hard
        g->speed = 150;
        g->speedMin = 30;
    }
    //Version4.0新增 双人模式的初始化：玩家2的蛇、第二个食物、倒计时
    if (g->mode == 1) {
        int cy2 = H * 2 / 3;   //玩家2在下半区
        g->snakeLen2 = 3;
        g->snake2[0].x = cx;     g->snake2[0].y = cy2;
        g->snake2[1].x = cx - 1; g->snake2[1].y = cy2;
        g->snake2[2].x = cx - 2; g->snake2[2].y = cy2;
        g->score2 = 0;
        g->timeLeft = MATCH_TIME;
        g->timeAcc = 0;
        g->winner = 0;
        //两个食物都要避开两条蛇，重新生成
        SpawnFoodDuel(g, false);
        SpawnFoodDuel(g, true);
    }
}
void Step(Game &g, int dirX, int dirY){
    //计算新蛇头坐标
    int nextX=g.snake[0].x+dirX;
    int nextY=g.snake[0].y+dirY;
    //撞墙检测
    if (nextX<=0||nextX>=W-1||nextY<=0||nextY>=H-1){
        g.over=true;
        g.deathreason=1;    //V5新增 记录死因 撞墙
        return;
    }
    //ate判断是否吃到食物（头坐标与食物坐标一致判定为吃到了）
    bool ate=(nextX==g.food.x && nextY==g.food.y);
    //吃到食物了蛇身就延长一格
    if(ate==true && g.snakeLen<MAXLEN){ //修复BUG 蛇长度小于MAXLEN
        g.snakeLen++;
        //Version2.0新增 每吃到一个食物speed-5 最快不小于50
        g.speed-=10;                // ★V3.0修改：原为 speed-=5，现统一每吃一个 -10
        if(g.speed<g.speedMin){     // ★V3.0修改：下限按难度决定，原为写死的 50
            g.speed=g.speedMin;     //限制最快速度
        }
    }
    //蛇移位
    for (int i=g.snakeLen-1;i>0;i--){
        g.snake[i]=g.snake[i-1];
    }
    //新头
    g.snake[0].x=nextX;
    g.snake[0].y=nextY;
    //检测是否撞到自己 下一时刻的蛇头是否与蛇身坐标相等
    for (int i=1;i<g.snakeLen;i++){
        if (g.snake[0].x==g.snake[i].x && g.snake[0].y == g.snake[i].y){
            g.over=true;
            g.deathreason=2; // 记录死因 撞自己
            return;
        }
    }
    //修复BUG 把SpawnFood挪到蛇头更新之后
    if(ate==true){
        g.score++;
        SpawnFood(&g);
        //Version2.0新增 每次吃到食物 对比并更新最高分
        if (g.score>g.highestscore) {
            g.highestscore=g.score;
        }
    }
}
//Version4.0新增 双人模式一帧：两条蛇同时移动、互撞判定、吃食物、计分
static void StepDuel(Game &g, int dirX1, int dirY1, int dirX2, int dirY2)
{
    //两条蛇各自的新蛇头
    int nx1 = g.snake[0].x + dirX1;
    int ny1 = g.snake[0].y + dirY1;
    int nx2 = g.snake2[0].x + dirX2;
    int ny2 = g.snake2[0].y + dirY2;
    //撞墙判定
    bool wall1 = (nx1<=0||nx1>=W-1||ny1<=0||ny1>=H-1);
    bool wall2 = (nx2<=0||nx2>=W-1||ny2<=0||ny2>=H-1);
    //是否吃到食物（撞墙的蛇不判定吃）
    bool ate1 = (!wall1) && (nx1==g.food.x  && ny1==g.food.y);
    bool ate2 = (!wall2) && (nx2==g.food2.x && ny2==g.food2.y);
    //吃到食物就加长；全场速度加快（两人共用速度，公平）
    if (ate1 && g.snakeLen < MAXLEN) {
        g.snakeLen++;
        g.speed -= 10;
        if (g.speed < g.speedMin) g.speed = g.speedMin;
    }
    if (ate2 && g.snakeLen2 < MAXLEN) {
        g.snakeLen2++;
        g.speed -= 10;
        if (g.speed < g.speedMin) g.speed = g.speedMin;
    }
    //蛇移位 + 写新头（撞墙的蛇保持原地）
    if (!wall1) {
        for (int i=g.snakeLen-1; i>0; i--) g.snake[i]=g.snake[i-1];
        g.snake[0].x=nx1; g.snake[0].y=ny1;
    }
    if (!wall2) {
        for (int i=g.snakeLen2-1; i>0; i--) g.snake2[i]=g.snake2[i-1];
        g.snake2[0].x=nx2; g.snake2[0].y=ny2;
    }
    //撞自己
    bool self1=false, self2=false;
    if (!wall1) {
        for (int i=1; i<g.snakeLen; i++)
            if (g.snake[0].x==g.snake[i].x && g.snake[0].y==g.snake[i].y) self1=true;
    }
    if (!wall2) {
        for (int i=1; i<g.snakeLen2; i++)
            if (g.snake2[0].x==g.snake2[i].x && g.snake2[0].y==g.snake2[i].y) self2=true;
    }
    //两条蛇互相碰撞：头碰到对方任意一节（包括对方头）
    bool hit1=false, hit2=false;
    if (!wall1) {
        for (int i=0; i<g.snakeLen2; i++)
            if (g.snake[0].x==g.snake2[i].x && g.snake[0].y==g.snake2[i].y) hit1=true;
    }
    if (!wall2) {
        for (int i=0; i<g.snakeLen; i++)
            if (g.snake2[0].x==g.snake[i].x && g.snake2[0].y==g.snake[i].y) hit2=true;
    }
    //汇总死亡
    bool dead1 = wall1 || self1 || hit1;
    bool dead2 = wall2 || self2 || hit2;
    //吃食物加分、补充新食物（死了就不加分）
    if (!dead1 && ate1) { g.score++;  SpawnFoodDuel(&g, false); }
    if (!dead2 && ate2) { g.score2++; SpawnFoodDuel(&g, true);  }
    //结束判定：一方死亡另一胜；同时死亡按得分；分数相同为平局
    if (dead1 || dead2) {
        g.over = true;
        if (dead1 && dead2) {
            if      (g.score > g.score2) g.winner = 1;
            else if (g.score < g.score2) g.winner = 2;
            else                         g.winner = 3;
        } else if (dead1) {
            g.winner = 2;
        } else {
            g.winner = 1;
        }
    }
}
static void BuildFrame(Game *g)
{
    int x, y, i;
    //全部清空
    for(y=0;y<H;y++){
        for(x=0;x<W;x++){
            g->grid[y][x]=' ';
        }
    }
    //左右墙
    for(y=1;y<H-1;y++){
        g->grid[y][0]     = '|';
        g->grid[y][W - 1] = '|';
    }
    //食物
    //修复BUG 将食物先绘制出来 使得蛇不被盖住
    g->grid[g->food.y][g->food.x] = '$';
    //蛇身
    for (i=g->snakeLen-1;i>=1;i--){
        g->grid[g->snake[i].y][g->snake[i].x] = 'o';
    }
    //蛇头
    g->grid[g->snake[0].y][g->snake[0].x] = '@';
    //Version4.0新增 双人模式：补画第二个食物和玩家2的蛇
    if (g->mode == 1) {
        g->grid[g->food2.y][g->food2.x] = '$';
        for (i=g->snakeLen2-1; i>=1; i--) {
            g->grid[g->snake2[i].y][g->snake2[i].x] = 'x';
        }
        g->grid[g->snake2[0].y][g->snake2[0].x] = '#';
    }
}

## 7. 开发总结

### 7.1 最大的难点：不是 C++ 语法，是"帧"的思维

之前的程序都是"执行一遍就结束"：输入、计算、输出，一条线走到底。贪吃蛇是**实时程序**：它有一个自己转的时钟（`Sleep`），每一拍做同样的事——读键、算一步、重画、再等下一拍。代码要正确，前提是每一拍内部的**动作顺序**都不能乱。

实际踩过、也最能说明这一点的三个坑：

- **V3 蛇不动、程序死循环**：`Step` 里算了新蛇头，却没把 `snake[0]` 更新过去。蛇头坐标永远不变 → 永远不会撞墙 → `while(!over)` 永远转。这是"以为算完了就是发生了"。
- **V4 食物偶尔出现在蛇头下**：`SpawnFood` 写在了蛇头更新**之前**，此时 `OnSnake` 看到的是旧蛇、看不到新头，于是食物可能正好生成在新头那一格。这是"操作顺序"直接决定了"数据对不对"。
- **Version 2.0 编译通过、终端却一片空白**：`ios::sync_with_stdio(false)` + `endl` 换成 `'\n'` 之后输出攒在缓冲里，程序又永远不退出，画面就"看起来没运行"。这是"看不见的现象背后有一个没被刷新的事实"。

所以最大的难点是：**建立"游戏状态 → 每帧重建 → 整体重画"的循环世界观，并且理解每个动作的先后顺序会直接决定结果对错。** 这类 bug 不报错、不崩溃，只是"看起来哪里不对"，是最难查的一类。

### 7.2 学到的方法

1. **迭代开发是真的能用的。** 从 V1 一个静止的框开始，每一版只加一件东西、有一个可验收的标准。如果一上来就写完整游戏，卡住的地方会十倍以上。

2. **调试是"缩小问题"，不是"盯着代码看"。** V3 先做"不接键盘、蛇自动走"的最小版本，就是为了把"键盘"和"移动"两个变量分开。食物看不见，很快定位到 `PutCell` 的 `case`；画面空白，最后定位到缓冲——都是靠"现象 → 可能原因 → 只改一处验证"。

3. **数据和画面要分开。** `grid` 是"这一帧画什么"，`snake` 是"游戏状态"。`BuildFrame` 只写字符，`DrawFrame` 只输出。改显示（改字符、改对齐、改宽窄）时不用动逻辑，改逻辑时不用动显示——这个分层省了很多次重写。

4. **边界情况要主动想，而不是等它撞上。** 蛇头进旧尾巴那格算不算撞（尾巴特例）、吃到时尾巴留不留、移动方向反不反向、菜单比画面宽会不会残留——这些都不是"运行出错才去想"的，而是写之前就该问自己的。

### 7.3 理解更深刻的知识点

| 知识点 | 经历 |
|---|---|
| **数组与结构体** | `snake[]` 存的是"顺序"而不是"位置"；`grid[H][W]` 是"画面"。`struct Game` 把状态打包，`Game*`/`Game&` 传参，不用全局变量 |
| **循环与状态机** | `while(true)` 外层（管重开）+ 内层（管一局），`over` 标志而不是 `exit(0)`，才有了 V5 的"死亡后还能重开" |
| **指针与引用** | `InitGame(Game*)` 改写对象、`DrawFrame(const Game*)` 只读、`Step(Game&, ...)`，什么时候用指针什么时候用引用，在改错里体会过 |
| **随机数** | `srand` 只种一次、`rand()%范围` 的区间、`do...while` 拒绝采样（不落在蛇身上）——最简单的"重试直到合法" |
| **函数划分** | `SpawnFood` 只生成不画、`PutCell` 只画一个格、`BuildFrame` 只组装——一个函数一件事，出错时能瞬间定位到层 |
| **I/O 与缓冲 / 控制台 API** | `cls` 闪屏的本质是"清空再画之间的空档"；`SetConsoleCursorPosition` 是"直接覆盖"；`_kbhit` 不阻塞、`_getch` 两字节方向键；`cout` 的缓冲和 `endl` 的 flush |
| **坐标与字符宽度** | 行列从 0 开始、`y` 是行 `x` 是列、字符宽约为高的 1/2、2 字符格和 1 字符格的取舍 |

### 7.4 最终收获

完成的其实是一个**完整的软件迭代**：需求拆分 → 设计约定 → 每版实现 → 自测验收 → 修 bug → 加难度/菜单 → 收尾。C++ 语法在这段经历里只是工具，真正长出来的是"怎么把一个想法变成一个能跑、能改、能扩展的程序"。

## 8. 指针与引用详解

项目里同一个 `Game` 交给函数，用了三种写法：`Game*`、`Game&`、`const Game&`。

### 8.1 函数签名

```cpp
static void InitGame(Game *g);           // 指针，要改写
void Step(Game &g, int dirX, int dirY);  // 引用，要改写
bool OnSnake(const Game &g, int x, int y); // const 引用，只读
static void DrawFrame(const Game *g);    // const 指针，只读
```

两张轴：

| | 要改对象 | 只读不写 |
|---|---|---|
| **指针** | `Game* g`（InitGame / BuildFrame / SpawnFood） | `const Game* g`（DrawFrame） |
| **引用** | `Game& g`（Step） | `const Game& g`（OnSnake） |

### 8.2 为什么"要改写"的既用指针又用引用

它们**功能上等价**——改的都是外面那个 `game`——区别在语法和约束：

```cpp
InitGame(&game);        // 指针：调用端显式取地址
Step(game, dirX, dirY); // 引用：调用端像传值一样，干净
```

函数体里也一样：

```cpp
g->snakeLen = 3;   // 指针：用 ->
g.snakeLen = 3;    // 引用：用 .
```

引用的两个好处：

1. **引用不能为空。** 引用必须绑定到一个对象，`Step(nullptr, 0, 0)` 根本编译不过；而指针可能拿到空指针，`InitGame(nullptr)` 会在解引用时崩掉。
2. **引用不能中途换目标。** 函数里 `g = other` 对引用是"赋值"，对指针是"改指向"。不需要改指向时，引用更贴合意图。

指针的用途：**可选参数**（"没有就传 nullptr"）、**动态内存**、**数组**（数组名传参退化成指针）。

### 8.3 为什么"只读"的要加 `const`

`const` 是给编译器的承诺：**这个函数不会改你传进来的对象**。

- `OnSnake(const Game &g)`：函数里写 `g.snakeLen = 0;` 直接编译报错。不是靠自觉，是编译器帮你拦。
- `DrawFrame(const Game *g)`：同理，`g->score = 1;` 编译不过。

好处：防手滑（画图函数里顺手改数据，逻辑就乱了）；**接口即文档**——看签名就知道这个函数是读还是写。

只读还用指针/引用、不直接值传递，是因为 `Game` 很大：`snake[1250]` 约 10KB，`grid[25][50]` 又 1.25KB。值传递会**复制一份**再进函数——每帧 `Step` 都复制 11KB，不是错但白费功夫；而且函数里改的是副本，外面看不到。所以"只读大对象"的标准写法就是 `const 引用`。

### 8.4 三种传参的本质区别

| 对比项 | 值传递 `Game g` | 指针 `Game*` | 引用 `Game&` |
|---|---|---|---|
| 函数内改对象，外面变吗 | **不变**（改副本） | 变 | 变 |
| 能否为空 | 不涉及 | 能（`nullptr`） | **不能** |
| 能否换指向 | — | 能 | 不能 |
| 访问成员 | `.` | `->` | `.` |
| 复制开销 | 整份拷贝 | 只传地址 | 只传地址 |
| 典型用途 | 小对象（`int`、`char`） | 可选参数、数组、动态内存 | 必传参数、只读大对象 |

### 8.5 如果写错，会发生什么

- **`void Step(Game g, ...)`（值传递）**：编译通过、运行不报错，但蛇永远不动——因为改的是副本。这类错误最阴，因为"看起来什么都没坏"。
- **`InitGame(nullptr)`**：编译通过，运行崩。用引用就编译不过。
- **`DrawFrame(Game *g)` 漏了 `const`**：能跑，但哪天在画图逻辑里不小心改了 `score`，会排查很久。
- **指针写成 `g.snake`**：编译不过，编译器会提醒你"`g` 是指针，用 `->`"。

### 8.6 选择口诀

1. **要改对象** → 首选引用（非空、干净）；**需要表达"可能没有"** → 用指针。
2. **只读大对象** → `const 引用`（非空）或 `const 指针`（可空）。
3. **数组** → 只能指针（数组名退化为指针）。
4. **小对象**（`int`、`char`、坐标 `Point`） → 值传递最自然。
5. **要在函数里改指向** → 指针（引用做不到）。

### 8.7 加深理解的小实验

1. 把 `InitGame(Game *g)` 改成 `InitGame(Game &g)`，函数体里 `g->` 全部改成 `g.`，调用处 `InitGame(&game)` 改成 `InitGame(game)`，编译运行——体会"引用让调用端和函数体都更干净"。
2. 在 `DrawFrame` 里故意写一行 `g->score = 1;`，编译，看报错信息长什么样——以后看到 "assignment of read-only …" 就知道是 const 在拦你。
3. 把 `OnSnake` 的 `const` 去掉，再编译——不报错，但这不是鼓励删 const，而是看清"const 是自愿加的约束"。

## 9. 环境与踩坑清单

### 9.1 编译与运行

- 编译加 `-std=c++17 -Wall -Wextra`，警告全开。大一阶段 80% 的"玄学 bug"编译器早就警告过。
- `<windows.h>` 和 `<conio.h>` 不需要额外链接库，MinGW 直接可用。
- 调试时优先"外部终端运行 exe"，集成终端的按键行为偶尔会和你想的不一样。

### 9.2 五个真实环境的坑

1. **中文乱码**：MinGW 源码 UTF-8 + Windows 终端默认 GBK(936) → 中文变乱码。对策：V1 起全用 ASCII 字符画；确需中文就统一 `chcp 65001` + UTF-8 源文件，或源文件存成 GBK。
2. **控制台"快速编辑模式"**：鼠标在窗口里点一下选中文字，程序会在下次输出时**卡住**，看起来像死循环。对策：`InitConsole` 里用 `SetConsoleMode` 关掉 `ENABLE_QUICK_EDIT_MODE`，或提醒自己别点窗口。
3. **滚屏错位**：任何 `\n` 输出到窗口底部都会把整屏顶上去。对策：逐格定位，不在场地内用换行。
4. **方向键两字节**：`_getch()` 先返回 0 或 224，第二次才是 72/80/75/77。
5. **闪烁其实不怪 Sleep**：怪的是清屏。很多人加 `Sleep`、加 `fflush` 治不好，方向就错了。

### 9.3 其他细节

- `Sleep` 精度约 15.6 ms，`Sleep(5)` 可能实际睡 15 ms。
- `_getch()` 返回值应存 `int`（方向键两字节）。
- 每帧 `while(_kbhit())` 读空缓冲，避免按键积压。
- 重开要彻底：蛇、方向、分数、食物、状态、计时器全部重置。
- 最高分比较必须放在 `score++` 之后。
- `ios::sync_with_stdio(false)` 会让 `cout` 全缓冲；若用 `'\n'` 代替 `endl` 又不 flush，程序不退出时输出会攒在缓冲里。

### 9.4 学习习惯

- 每版开工前先在纸上画"这一版的数据流"：谁读谁、谁改谁。
- 每版结束打一个备份，V3 崩了能退回 V2 跑通的状态。
- 调 bug 先打印蛇的坐标序列和状态，比盯屏幕猜快十倍。
- 命名统一：函数用动词，常量全大写。
- 先让它"能跑"，再让它"好看"，最后才"重构"。
